# myopyc recorded-data format (v1)

This is the normative specification of the on-disk format produced by
`myopyc record` and read back by `myopyc.recorder`. It applies to every
session whose manifest carries `format: "myopyc.session"` and
`format_version: 1`.

The single source of truth for dtypes is
[`src/myopyc/streams/schema.py`](https://github.com/acabtech/myopyc/blob/main/src/myopyc/streams/schema.py);
the manifest writer lives in
[`src/myopyc/recorder/manifest.py`](https://github.com/acabtech/myopyc/blob/main/src/myopyc/recorder/manifest.py).

## Session layout

A session is one self-contained directory:

```
20261117_142530_ab12cd/
├── manifest.json
└── devices/
    ├── left/
    │   ├── emg/chunk-00000.npy
    │   ├── emg/chunk-00001.npy
    │   ├── imu/chunk-00000.npy
    │   └── event/chunk-00000.npy
    └── right/
        ├── emg/chunk-00000.npy
        └── imu/chunk-00000.npy
```

- Session directory names are `<UTC timestamp>_<6 hex chars>[_<name>]`; the
  name part is optional user decoration and carries no meaning.
- There is exactly one `.npy` chunk **per (device, stream kind) per flush**.
  Chunk indices start at 0 per device/stream and count up in flush order
  (`chunk-00000.npy`, `chunk-00001.npy`, ...).
- Chunks are **immutable once written**: the recorder never appends to or
  rewrites an existing `.npy`. Repair (`myopyc inspect --repair`) likewise
  never rewrites chunk data — it only moves untrustworthy files into
  `unrepaired/` (quarantine) and reconciles the manifest.
- `manifest.json` is always written **atomically** (write to a `.tmp` file,
  then `os.replace`), so a crash can only ever leave the *previous* manifest
  or a `.tmp` remnant, never a half-written manifest.
- If a repair performed a manifest rewrite, the previous manifest is kept as
  `manifest.json.bak` (first repair only; later repairs do not overwrite it).
- **Session resume** (v0.2, additive): an interrupted session (`status="recording"`)
  can be repaired/reconciled and then resumed. Resume keeps the same session
  directory/id and appends a **new continuing chunk series**: new `.npy` files
  use chunk indices after the highest existing chunk index on disk/manifest, so
  previously recorded chunks are never overwritten. Resume metadata is recorded
  as append-only optional manifest fields (`resumed_utc`, `resume_count`,
  `resume_history`); `FORMAT_VERSION` remains 1.

## Manifest structure

Top-level keys (v1):

| Key | Type | Meaning |
|---|---|---|
| `format` | string | Always `"myopyc.session"`. Identifies the file type. |
| `format_version` | integer | Always `1` for the format documented here. |
| `session_id` | string | `<UTC timestamp>_<6 hex chars>`, the canonical session id. |
| `app_version` | string | `myopyc.__version__` that wrote the session. |
| `created_utc` | string | ISO-8601 UTC start time, millisecond precision, `Z` suffix. |
| `stopped_utc` | string \| null | Finalisation time; `null` while recording. |
| `status` | string | `"recording"`, `"stopped"`, or `"repaired"`. |
| `timebase` | string | Always `"host-monotonic-ns"`; see [Timebase](#timebase-and-t_ns). |
| `notes` | string | Optional free-text session note (operator/protocol/context), added as an append-only optional top-level field in v0.2. Absent/empty means no note; readers must treat a missing field as `""`. |
| `chunking` | object | `{ "mode": "time", "flush_interval_s": <float>, "max_ram_bytes": <int> }` — the recorder settings that produced this session. |
| `devices` | object | Keyed by device key (see below). |
| `gaps` | array | Every drop event; see [Gaps](#gaps-and-drop-accounting). |
| `markers` | array | Optional; user annotations, see [Markers](#markers). Added as an append-only optional top-level field in v0.2; absent in sessions recorded without any. |
| `resumed_utc` | string | Optional; ISO-8601 UTC time of the most recent resume action. Append-only optional field; absent for sessions never resumed. |
| `resume_count` | integer | Optional; number of times recording was resumed into a continuing chunk series. Append-only optional field; absent means 0. |
| `resume_history` | array | Optional; append-only list of resume events (e.g. `{ "resumed_utc": ... }`). Readers must ignore unknown entries/fields. |

Device key: real Myos are keyed by their MAC address; simulated armbands get
a synthetic key (e.g. `sim-<n>` style ids generated by the device manager).
Each device entry:

| Key | Type | Meaning |
|---|---|---|
| `label` | string | User-facing name (`"Left"`, `"Right"`, ...). |
| `mac` | string \| null | MAC address for real hardware; `null` for simulated devices. |
| `name` | string | Adapter-reported device name (default `"Myo"`). |
| `firmware` | string \| null | Firmware version when known. |
| `streams` | object | Keyed by stream kind (`"emg"`, `"imu"`, and possibly others in future versions). |

Each stream entry:

| Key | Type | Meaning |
|---|---|---|
| `sample_rate_hz` | float | Expected nominal rate (EMG 200.0, IMU 50.0). |
| `dtype` | string | NumPy structured-dtype `str()` of the chunk arrays. |
| `columns` | array | Per-column `{ "name", "unit", "description" }`. |
| `notes` | string | Human-readable stream description. |
| `chunks` | array | The chunk index, in write order; see below. |
| `samples` | integer | Total samples written across all chunks. |
| `dropped_samples` | integer | Total samples dropped for this stream (RAM overflow only; BLE-level loss before receipt is not countable and shows up as gaps in time instead). |

Chunk entries (one per `.npy` file):

| Key | Type | Meaning |
|---|---|---|
| `file` | string | Relative POSIX path from the session root, e.g. `devices/left/emg/chunk-00000.npy`. |
| `samples` | integer | Number of records in the chunk. |
| `t_start_ns` | integer | `t_ns` of the first record. |
| `t_end_ns` | integer | `t_ns` of the last record. |
| `bytes` | integer | Size of the `.npy` file on disk at write time. |

The set of stream kinds a session may carry is not fixed at `1`: v1 sessions
record `emg` and `imu` from the start, and the event-driven `event` kind was
added later in v0.2 as an append-only optional stream (see
[EVENT](#event-deviceskeyeventchunk-nnnnnpy)). `FORMAT_VERSION` remains `1`;
readers must skip stream keys they do not know.

## Chunk dtypes

Chunks are NumPy structured arrays saved with `np.save(..., allow_pickle=False)`,
little-endian (`<`) byte order on all platforms.

### EMG (`devices/<key>/emg/chunk-NNNNN.npy`)

| Field | Dtype | Unit | Meaning |
|---|---|---|---|
| `t_ns` | `<i8` | ns | Host monotonic receive time; see [Timebase](#timebase-and-t_ns). |
| `seq` | `<i8` | 1 | Per-stream sequence counter, starts at 0, increments by 1 per sample; survives disconnect/reconnect for the same device key. |
| `ch1` ... `ch8` | `i1` | int8 | Raw, unfiltered EMG channels as delivered by the Myo (8-bit signed). |

Expected rate: ~200 Hz per channel.

### IMU (`devices/<key>/imu/chunk-NNNNN.npy`)

| Field | Dtype | Unit | Meaning |
|---|---|---|---|
| `t_ns` | `<i8` | ns | Host monotonic receive time. |
| `seq` | `<i8` | 1 | Per-stream sequence counter, independent of the EMG counter. |
| `qw`, `qx`, `qy`, `qz` | `<f4` | quaternion | Orientation quaternion (w last-written-first convention: `(w, x, y, z)`). |
| `ax`, `ay`, `az` | `<f4` | g | Accelerometer in g. |
| `gx`, `gy`, `gz` | `<f4` | deg/s | Gyroscope in degrees per second. |

Expected rate: ~50 Hz.

### EVENT (`devices/<key>/event/chunk-NNNNN.npy`) { #event-deviceskeyeventchunk-nnnnnpy }

| Field | Dtype | Unit | Meaning |
|---|---|---|---|
| `t_ns` | `<i8` | ns | Host monotonic receive time. |
| `seq` | `<i8` | 1 | Per-stream sequence counter, independent of the EMG/IMU counters; survives disconnect/reconnect for the same device key. |
| `type` | `u1` | code | Gesture/pose code: `0` = no pose, `1` = fist, `2` = wave_left, `3` = wave_right, `4` = double_click. Unknown codes must be tolerated (render as `unknown-<n>`); new codes may be added append-only. |
| `ox`, `oy`, `oz`, `ow` | `<f4` | quaternion | Packed orientation payload captured at event time (quaternion `(x, y, z, w)`); zeroed when not applicable. |

Expected rate: none — the EVENT stream is **event-driven**, so its manifest
`sample_rate_hz` is `0.0` and readers must not infer a rate or staleness from
it. Introduced in v0.2 as an additive third stream kind (per the append-only
contract below); v0.1 readers skip it, and sessions that carry it remain
valid v1 sessions.

## Timebase and `t_ns`

- `t_ns` is a **host monotonic** nanosecond timestamp taken when the sample
  batch is received from the BLE transport on the host — it is *not* the
  Myo's internal hardware clock and not a wall-clock time.
- It is suitable for: ordering samples within a stream, reconstructing the
  recording timeline, and best-effort alignment between two armbands.
- It is **not** a hardware-synchronised clock: cross-device alignment is only
  as good as BLE receive jitter, and `t_ns` values from different devices are
  not guaranteed to share a common zero beyond "same host boot".
- Monotonicity: within one device stream, `t_ns` is non-decreasing across
  chunks (chunks are written in receive order). Two devices have unrelated
  offsets.
- To convert to relative seconds: `t_seconds = (t_ns - t_ns[0]) / 1e9`.
  To correlate with wall-clock time, use the manifest's `created_utc`
  (start of recording) as an approximation anchor.
- The manifest's `timebase: "host-monotonic-ns"` field names this convention
  so a future version could switch (e.g. to hardware timestamps) without
  ambiguity.

## Gaps and drop accounting

The recorder is RAM-first: samples are buffered in memory and flushed to disk
every `flush_interval_s`. The design priority is to **never stall the BLE
stream**; when the RAM budget (`max_ram_bytes`, split evenly across all
device/stream buffers) is exceeded between flushes, the *oldest* buffered
samples for that stream are dropped and the loss is recorded explicitly.

A gap entry in the top-level `gaps` array:

```json
{
  "device": "<device key>",
  "stream": "emg",
  "reason": "ram-buffer-overflow",
  "t_start_ns": 1731843930123456789,
  "t_end_ns": 1731843931123456789,
  "samples": 200,
  "recorded_utc": "2026-11-17T14:25:31.123Z"
}
```

| Field | Meaning |
|---|---|
| `device` | Device key whose stream lost samples. |
| `stream` | Stream kind that lost samples. |
| `reason` | `"ram-buffer-overflow"` in v1. New reasons may be added (append-only); readers must tolerate unknown reasons. |
| `t_start_ns` / `t_end_ns` | Host-monotonic span of the *dropped* samples — this is the interval of the timeline with no data. |
| `samples` | Number of dropped records. |
| `recorded_utc` | When the drop was recorded. |

Semantics a reader can rely on:

- Between the end of one surviving chunk and the start of the next, the
  timeline may contain dropped samples; `gaps` is the authoritative record of
  *how much* is missing and *why*.
- `t_start_ns`/`t_end_ns` of a gap fall inside the dropped (never-written)
  samples, so a gap never overlaps a surviving chunk's span.
- `dropped_samples` in the per-stream entry is the running total of
  samples dropped for that stream; it equals the sum of that stream's gap
  `samples`.
- Chunks themselves never encode gaps — a chunk always contains a contiguous
  run of received samples in receive order.

## Markers

A marker is a user annotation on the session timeline: a host-monotonic
timestamp, a short label and an optional free-text note, scoped to the whole
session rather than to one device. Markers live in the optional top-level
`markers` array — purely additive under the append-only contract, so
`FORMAT_VERSION` stays 1 and v0.1/v0.2 readers that predate markers simply
ignore the key.

```json
{
  "label": "task start",
  "t_ns": 1731843931500000000,
  "note": "participant 7, hand open",
  "created_utc": "2026-11-17T14:25:31.500Z"
}
```

| Field | Meaning |
|---|---|
| `label` | Short user-facing name (non-empty string). Required. |
| `t_ns` | Host-monotonic timestamp on the same timebase as the streams' `t_ns`; see [Timebase](#timebase-and-t_ns). Required. |
| `note` | Free-text annotation; empty string when absent. |
| `created_utc` | Optional; when the marker was injected (ISO-8601 UTC, `Z` suffix). |

Injection: `myopyc record --marker-file markers.jsonl` reads one JSON object
per line (`{"label": ..., "offset_s": <s> | "t_ns": <ns>, "note": <str>?}`;
blank lines and `#` comments are skipped). `offset_s` markers are resolved
against the recording start on the same host-monotonic clock the streams use,
so a marker at `offset_s: 2.5` sits exactly 2.5 s into the session timeline.
`offset_s`/`t_ns` markers resolved to the same nanosecond as a stream sample
mark that instant — alignment with EMG/IMU/EVENT rows is exact by
construction, since all share the timebase.

Semantics a reader can rely on:

- Markers never carry device scope; they annotate the whole session.
- `t_ns` may fall anywhere inside (or slightly outside) the recorded span;
  readers must not assume a marker aligns with a sample.
- Unknown fields in a marker entry may appear in future versions and must be
  preserved (they are: readers return the raw manifest untouched).

## Crash safety and repair

If the process dies mid-flush, the on-disk state can disagree with the
manifest in three ways, all handled by
[`repair_session()`](https://github.com/acabtech/myopyc/blob/main/src/myopyc/recorder/repair.py)
(`myopyc inspect --repair`):

1. **Orphaned chunk** — `.npy` written but never registered in the manifest
   (process died before the atomic manifest rewrite). Quarantined into
   `unrepaired/`.
2. **Truncated chunk** — partially written `.npy` from an interrupted save;
   fails to load or has the wrong dtype. Quarantined into `unrepaired/`.
3. **Missing chunk** — listed in the manifest but absent on disk. Its
   manifest entry is dropped and per-stream sample counts are recomputed
   from the surviving chunks.

Repair never rewrites or deletes chunk data, is idempotent, and flips a
still-`"recording"` session to `"repaired"` so it is never mistaken for an
active capture. Data through the last completed flush is preserved exactly.

## Append-only evolution contract

`FORMAT_VERSION` stays **1** and the format evolves only additively.

### Known v0.2 additive fields

These fields were added after the initial v0.1 format and are valid examples of
the contract in practice:

- **`notes`** (top-level, optional string): free-text session note; missing means
  `""`.
- **`markers`** (top-level, optional array): session-scoped annotations with
  `label`, `t_ns`, optional `note`/`created_utc`; missing means no markers.
- **`event` stream kind** (`devices.<k>.streams.event`, optional): event-driven
  gesture/pose chunks using
  [`EVENT_DTYPE`](https://github.com/acabtech/myopyc/blob/main/src/myopyc/streams/schema.py);
  missing means the session has no event stream.

### Writer rules

Writers may:

- add new optional top-level manifest fields;
- add new optional per-device or per-stream fields;
- add new optional per-chunk fields;
- add new gap `reason` values;
- add entirely new stream kinds (a new key under `devices.<k>.streams` with
  its own chunk directory).

Writers must not:

- remove or repurpose existing fields;
- change the meaning, unit, or dtype of an existing field;
- make a previously optional field required.

### Reader rules

Readers must:

- ignore keys (at any level) and stream kinds they do not understand;
- not require any newly added optional field to be present;
- treat a missing field the same as in v0.1 sessions.

The result: a session written by any future 1.x tool remains readable by the
v0.1 reader, and a v0.1 session remains readable by all future 1.x readers.
Breaking layout or dtype changes require a future `format_version` bump, at
which point readers decide by `format_version` how to interpret the files.

Forward-compatibility is enforced by tests: readers are exercised against
manifests containing unknown keys and unknown stream kinds, and must skip
them without error.
